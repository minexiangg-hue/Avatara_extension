# Avatara 0.2 · 设计说明

这次重建以「留住思路，继续向前」为中心：帮助用户重新找到看过的东西，看清正在关心的方向，再迈出一个自己认可的小步骤。它既需要浏览器的即时上下文，也需要一个能回顾过去的私人空间。

这是新实现的产品与设计基线，源码位于 `D:\DshWorkspace\Avatara_next`。旧项目 `D:\DshWorkspace\Avatara_extension` 保留，用来理解原有目标；没有在旧界面上继续叠加样式，也不自动迁移旧数据。

## 信息结构

四个主空间分别对应一个明确的问题：

| 空间 | 用户此刻的问题 | 界面优先呈现 |
| --- | --- | --- |
| 今日 | 我可以从哪里继续？ | 个人关注、最近阅读、少量目标、快捷提问。 |
| 记忆 | 我之前在哪里看到过？ | 搜索、标题与来源、时间、摘录、收藏状态。 |
| 目标 | 我想往哪里走？ | 自己写下的初衷、可记录的数量、当前进度。 |
| 对话 | 能不能陪我把它理清？ | 问题、基于已有记录的回答、可核对的证据。 |

设置放在次级位置，集中管理云端连接与数据边界。首页不展示缺乏依据的「理解度」「生产力分数」或推测性行为结论。记忆数量、目标进度和主题数量都来自实际状态；用户尚未记录内容时，界面应该帮助完成第一步。

## 视觉语言

整体采用带有纸张感的浅奶油底、鼠尾草绿和少量赭色。大面积表面安静，文本与交互保持足够清楚。衬线标题提供阅读与思考的气质，表单、导航和正文使用系统无衬线字体，照顾长时间使用和小窗口阅读。

| 基础色 | 当前令牌 | 用途 |
| --- | --- | --- |
| 纸张底 | `#f8f9f4` | 主画布。 |
| 侧栏底 | `#f0f2ea` | 导航区域，与内容轻微区分。 |
| 卡片底 | `#fffefa` | 输入、卡片与主要信息承载面。 |
| 墨色 | `#293d32` | 最重要的文字。 |
| 深绿 | `#365844` | 主要按钮和关键动作。 |
| 鼠尾草 | `#e5ebde` | 选中、轻量分区与辅助强调。 |
| 赭色 | `#ba945b` | 小面积点缀，避免成为第二套主色。 |

视觉层级主要由字号、留白、对齐与轻边框建立。页面像一份可持续整理的个人手记：标题简洁，内容可扫描，相关行动靠近相应信息。品牌标记、轨道插画和图标用本地 SVG／CSS 构造，不依赖外部图片服务，也没有运行时字体下载。

首页轨道中的「记忆、当下、方向」是概念插画，不是后台分析的可视化结果。它表达三个空间如何相互支撑，不承载虚构数值。

## 两种浏览方式

完整工作台适合回顾、搜索、管理目标和较长的对话。左侧导航保持定位，内容区在宽屏中分栏，让最近记忆与少量目标并列出现。

侧边栏复用同一套界面、状态与消息接口。在窄屏下，导航转到下方，内容变为单列，辅助说明适度收起，表单和目标卡片依然可操作。它不是另一套功能删减版，而是为并行阅读重新安排信息密度。

工具栏弹窗只承担短动作：保存当前页、打开侧边栏和打开完整工作台。当前页采集必须从用户正在阅读的网页获得授权；若正在浏览工作台本身，界面应引导用户回到要保存的网页。

## 交互原则

- 主动作就近出现：记忆旁收藏、目标旁记录一步、输入框旁发送。完成动作后有可读的状态反馈。
- 搜索优先支持实际线索，例如标题里的词、域名和已有标签。空结果明确说明当前记录没有匹配，不把它说成用户从未浏览过。
- 目标进度依据用户手动记录，不从页面停留或浏览次数推断已经完成的行动。
- 删除目标、清空对话和清空数据有明确的确认。清空全部数据需要输入「清空」，同时说明不影响 Chrome 本身的历史。
- 表单具有标签，图标按钮有可读名称，键盘焦点可见；模态框限制焦点范围并可用 Escape 关闭。减少动态效果的系统偏好会关闭动画。
- 回答正文按文本显示，来源链接只接受普通 HTTP(S) 地址。模型内容不成为页面脚本或任意 HTML。

## 记忆如何进入回答

本地模式先召回相关资料，再给出原文短摘录、来源和朴素的目标建议。它的优势是离线、直接且可核对，界面会明确显示「本机整理」。

云端模式通过用户主动配置的服务补充归纳能力。只发送与本次问题相关的少量资料和近期对话；目标问题可附带少量目标摘要。页面、标题、URL、目标和历史对话都被当成不可信数据，而不是可以改变规则的指令。回答不能宣称已经执行没有发生的浏览器动作。

数字引用校验只能确认引用对应输入资料，不能保证模型的每个结论都正确。因此来源始终可打开核对，缺少证据时应说明不足。云端失败显示实际错误，不静默改成另一种回答后宣称成功。

主题由已有标签与明确的本地关键词归类生成，检索以关键词和字段权重为基础。这些是内容线索，不是对用户人格或长期习惯的确定判断。未找到明确关键词时，不强行归类。

## 数据与演示边界

真实扩展默认不自动采集，也不开启云端。历史权限与服务域名权限在相关操作中申请。浏览记忆、目标和对话保存在扩展本地状态中；API 密钥保存在独立的浏览器会话存储，关闭会话后需要重新输入。导出不包含密钥。

localhost 演示共享界面和领域模块，使用独立的合成数据运行时。示例账号 Alex、12 条记忆、3 个目标只用于体验布局和功能。演示不连接已安装扩展，也不使用真实浏览器历史或云端模型。UI 中的演示标记和设置说明必须保留。

52 项核心与模拟运行时测试已通过。普通 Chrome localhost 的关键交互、跨标签同步与 390 像素布局已实际验收。当前平台无法接管受限的扩展原生页面，真实安装环境的权限弹窗、侧边栏、当前页授权与后台生命周期仍需独立验收。视觉与网页演示通过不能替代扩展原生行为通过。

## 演进方向

这一版先提供可运行的采集、检索、来源回答与目标进度闭环。后续应优先改善用户能够感知的记忆质量，例如更好的正文抽取、明确的来源时效、用户可纠正的主题线索，以及真实扩展的持续验收。

更长远的个人助理可以逐步学会习惯、理解目标之间的关系并主动提供帮助，但这需要有依据的产品迭代。当前界面没有承诺自主付款、任意工具操作、书签自动同步、语义 embedding 检索或后台计划调度。
